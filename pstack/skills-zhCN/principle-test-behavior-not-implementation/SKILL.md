# Test Behavior, Not Implementation
（测试行为，而非实现）

测试是对代码使用者能通过接口观察到什么的断言：返回值、错误、能读回的状态、对外部系统的影响。私有辅助函数、内部调用顺序和中间数据都是实现。

用两个想象中的改动来评判每个测试：

- **破坏行为**（错误的值、被跳过或重复执行的效果）。如果测试仍然通过，它什么也没证明。常见原因是断言太松、期望值由被测代码算出、断言的数据是测试自己构造的。
- **改变内部实现**，保持每个可观察结果不变。如果测试失败，它就被钉死在实现上了。

保留能抓住第一种改动、又能扛住第二种改动的测试。其余的重写或删除。用具体输入通过公共接口驱动代码，从需求推导期望值。外部服务收到什么是行为，对内部辅助函数的调用不是。给「这绝不会发生」配一个它确实发生的用例。断言调用方据以分支的错误类型，而不是错误消息。
