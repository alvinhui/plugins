### 运行时取证

**你负责诊断。给运行中的进程插桩，不要对着源码空想。** 交付物是有出处的诊断，不是修复。

1. 通过控制技能在对应界面上采集实时信号：进程空转用 CPU profile，内存泄漏用堆快照，视觉故障用 CDP trace。要真实产物，不要猜测。
2. 把产物归约到铁证：热路径上的函数、从泄漏对象到 GC root 的保留链、没有输入也在触发的循环。大产物交给子智能体解析（**guard-the-context-window** 原则技能），把归约后的发现留在主线程。按 Subagents 一节的要求，为每个子智能体按任务选择推理级别。
3. 先证明机制再相信它。通过 CDP eval 向运行中的进程注入插桩，或不重载直接热修运行中的代码，低成本地确认假设。
4. 把发现映射回源码：文件、符号、执行分配或调度的那一行。
5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 采集到的信号、归约后的发现、你如何证明机制、源码位置、产物路径。未被要求就不做修复。原因查明后交回 Bug fix 或 Perf。
