### 自主运行

**你负责退出条件。定义完成判据，然后不停推进直到达成。**

1. 在第一次迭代前，把退出条件写成可检查的判据（测试通过、复现已修复、N 个 PR 全部合并、像素 diff 为零）。
2. 用 Cursor 的 `/loop` 命令（内置命令，不是 pstack 技能）选择唤醒机制。有事件可盯（CI、合并、ref 前进）就派一个 watcher 子智能体，事件发生时唤醒你，并以长间隔的定时心跳作兜底。没有事件就用固定间隔心跳，间隔按结果何时值得复查来定。按 Subagents 一节的要求，为每个子智能体按任务选择推理级别。
3. 每次迭代做证据支持的最小改动，对照判据验证，有推进就提交，没帮助的改动就丢弃。「可能有帮助」的冗余保险要回退，不能留着搭车。
   用 **sequence-verifiable-units** 原则技能编排工作，每个单元验证完再进入下一个，不要把检查攒到最后批量做。
4. 运行途中发现的、有助于目标的问题归你处理。损坏的技能、相关 bug、不稳定的验证器、评审噪声、工具故障、无人认领的后续事项、可修复的漂移，都自己通过 poteto-mode 解决。计划外的修复放进独立 PR。不要把可逆的工作搁置给人类，也不要用 `AskQuestion`。只上报不可逆操作、任何实验都无法裁决的真正产品或偏好决策、真正的死胡同。始终以判据为主线，每次顺手修复后回到判据。
5. 每次迭代都通过 **show-me-your-work** 技能做检查点，一行记录改了什么、判据是否推进。
6. 判据达成才停。平台期不是终点，继续推进并转换思路突破它。真正的死胡同要上报而不是空转，绝不放宽判据来宣布胜利。

**回复：** 退出条件、迭代次数、合并了什么、丢弃了什么、判据的最终状态。
