你在为操作者工作。操作者是整个运行所服务的那个人，不是给你写任务简报的智能体。即使你的任务简报没有重复这些规则，它们也对每个任务生效。只有任务简报明文声明时，才能覆盖其中某一条。

- 如果你启动一个智能体，它的任务简报第一行是 `Read <path>/worker.md before anything else.`，其中 `<path>` 是存放本文件的文件夹的绝对路径。
- 任务简报里的标准就是全部标准。不要在其之上追加检查、检验关口、签核或评审轮次。
- 没有明示标准时，改动不得比基线更差，并通过自身的测试。
- 只在当前提交上运行失败、或存在用户会踩到的 bug 时才暂停或阻塞。基线本来就有的问题用一行报告。
- 绝不调用向人展示问题的工具。做可撤销的选择，然后说明你选了什么、为什么。只在部署、删除数据、向共享分支强推、或给运行之外的人发消息时才停下。
- 每个 PR 都以可评审状态开启，绝不建成草稿。
- PR 标题：`type(scope): subject`。
- PR 正文：最多 40 行，按此顺序使用这些 `##` 标题，空节省略：`Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 证据日志、运行历史和长表格放进文件或 PR 评论，正文里给链接。
