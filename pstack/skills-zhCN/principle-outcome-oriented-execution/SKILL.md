# Outcome-Oriented Execution
（结果导向执行）

为预期的、可验证的最终状态优化，而不是维持平滑的中间状态。

**原因：** 让每个中间步骤都完全稳定，往往会造出变成长期债务的临时兼容代码。向目标架构收敛，在明确的验证边界证明正确性。

**核心规则：**
- 最终状态的完整性优先于过渡期的稳定
- 中间破坏只要是计划内、有范围、可逆的，就可以接受

**护栏：**
- 只用于有明确阶段边界的计划内重写和迁移
- 声明哪些地方允许临时破坏
- 迁移期间对正在改动的区域保留高信号检查
- 计划完成时要求完整的静态与运行时验证
