# Ketchup video（视频进展同步）

遵循 [`/ketchup`](../ketchup/SKILL.md)，但用一段带字幕的短视频代替它的摘要和视觉来展示发生了什么。窗口从用户在 `/ketchup-video` 之前写的最后一条消息起算，不是更早的某次 `/ketchup` 之前。在仓库外撰写并渲染视频，是其只读规则唯一的例外。回复由 ketchup 的开头一句、内嵌视频、一行点名你自己还能做的剩余工作，以及行动项组成。视频展示某个决策的选项时，按视频给的名字称呼每个选项。渲染失败就一行说明，只给决策。

## 幻灯片

用工作产出的截图、录屏、diff 和数据，不用会话里关于它们的文字。动笔前先写下用户看完应带走的那一句话，以及每页一行的要点。不改变用户认知的页删掉。至多 10 页，越少越好。这两份笔记都不进回复。

每页只讲一个点。整套幻灯片建立在同一张画面上，逐页演变，而不是切到无关的画面。一种颜色或形状在每页含义相同。用画面展示工作，比如系统如何工作、带各 PR 状态的 PR stack、修复前后对比、选项并排。用箭头、高亮和动效指出变化。幻灯片绝不是要点清单、状态清单、表格，或没有连线的方框。

文字压到最少。每个标签放在它指的东西上，写人会说的平实话，不写「Tests: pass」这种标签式短语。绝不给画面内容配说明文字，同一个事实绝不给两遍，无论跨页还是页下的文字里。

展示用户要求的每件事结果如何，是完成、仍在运行、失败还是未检查。仍在等用户的事绝不展示成完成。途中发现并修掉的 bug 要展示。可见变化没有截图时，在其页面上说明，并点名屏幕上变了什么。只用你掌握的事实画。绝不编造数字，绝不画你没截过的屏幕。

## 字幕

每页一条短字幕，约十个词，只依据该页展示的内容，按你会告诉用户的方式说出该页的点。说画面的含义，不照读标签。字幕放在页面下方的横条里，每页等高、除字幕外留空，绝不遮住页面。字号要小，但在会话尺寸播放时仍可读。

## 渲染

渲染一段无声横屏视频（如 mp4），页与页之间带动效。每一帧就是幻灯片本身，铺满画面，位于字幕条上方。帧由幻灯片生成，绝不靠录屏，并把每条字幕烧进该页的帧里，让它在该页整个停留期都在屏上。停留期指页面完整在屏的时间，不含切入切出的动效。每页停留时长要够读完它新增的词，每三个词至少一秒。一页新增的词包括它的字幕，以及上一页没有的每个词，含它改动的标签。第一页新增它的全部词。截图内部的词不计。

内嵌视频前检查渲染出的文件。按会话尺寸看每页各取一帧，确认字幕可读且不遮挡。停留期靠把文件帧与幻灯片逐帧匹配来量，不用静帧检测器——它会把淡入淡出的微弱尾端算作静帧。按量出的停留期核对每页新增词数。读不完的页修掉，重新渲染，再检查。
