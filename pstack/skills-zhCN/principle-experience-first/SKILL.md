# Experience First（体验优先）

实现的便利与用户的愉悦冲突时，选愉悦。

- 每个功能、控件和选项都必须有理由
- 少交付，交付得更好（三个功能的精致体验胜过十个功能的粗糙体验）
- 定案前先做原型（设计决策在一次性 HTML 里比在生产代码里更便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能要么服务于中心工作流，要么让开）

用户是消费这份工作成果的人。对 UI 来说，是最终用户。对库或内部 API 来说，是引入它的同事。接下来维护这份代码的工程师也是用户。用同样的方式权衡他们的体验，并从他们的视角解释影响。

地基应当服务于体验。Foundational Thinking 决定工作的*顺序*。本原则决定工作的*目标*。
